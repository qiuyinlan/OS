# 忙等待 (Busy Waiting)

**忙等待**，也称为**自旋**（Spinning）或**忙循环**（Busy Looping），是[[并发]]编程和[[操作系统]]中一种[[进程同步]]技术。它指的是一个[[进程 (Process)]]或[[线程 (Thread)]]在等待某个条件（如某个[[资源]]可用或某个[[锁]]被释放）成立时，不放弃[[中央处理器 (CPU)]]的使用权，而是反复执行一个循环来检查该条件。

## 核心机制
- 当[[进程 (Process)]]需要访问一个共享[[资源]]，但该[[资源]]当前不可用时，它不是进入[[阻塞]]状态（即放弃[[CPU]]并等待被唤醒），而是持续运行一个检查循环。
- `while (condition_not_met) { /* do nothing or check again */ }`

## 优缺点

### 优点
- **低延迟**: 如果等待时间非常短，忙等待可以避免[[上下文切换]]的开销。在多核[[中央处理器 (CPU)]]系统上，如果一个[[进程 (Process)]]预计很快就能获取锁，自旋比切换到另一个[[进程 (Process)]]再切换回来可能更快。
- **用于自旋锁**: 忙等待是[[自旋锁]]（Spinlock）实现的基础，[[自旋锁]]在[[内核空间]]中用于保护临界区，通常用于等待时间极短的场景。

### 缺点
- **浪费CPU周期**: 最大的缺点是[[中央处理器 (CPU)]]在等待期间被无效的计算占用，浪费了宝贵的[[CPU]][[资源]]，降低了[[中央处理器 (CPU)]]的利用率。
- **优先级反转**: 如果一个高优先级的[[进程 (Process)]]在忙等待一个被低优先级[[进程 (Process)]]持有的[[资源]]，而低优先级[[进程 (Process)]]无法获得[[中央处理器 (CPU)]]来释放[[资源]]，就会导致优先级反转问题。
- **不适合长时间等待**: 如果等待时间较长，忙等待的效率非常低，会严重拖慢系统性能。

## 替代方案
- **[[阻塞]]等待 (Blocking Wait)**: 当[[进程 (Process)]]需要等待时，它放弃[[中央处理器 (CPU)]]的控制权，进入[[阻塞]]状态，直到被等待的事件发生。[[操作系统]]可以将[[中央处理器 (CPU)]]分配给其他就绪的[[进程 (Process)]]。这是更常见的等待策略。
