# 中断向量表 (Interrupt Vector Table - IVT)

**中断向量表**（IVT）是[[操作系统]]和[[BIOS]]用于处理[[中断]]的一种核心[[数据]]结构。它本质上是一个存储着[[中断处理程序]]入口地址的数组。

## 核心作用
- **中断路由**: 当[[中央处理器 (CPU)]]接收到一个[[中断]]请求时，它需要知道应该跳转到哪段代码去处理这个[[中断]]。IVT就扮演着这个“路由表”或“分发表”的角色。
- **快速响应**: 通过查表的方式，[[中央处理器 (CPU)]]可以快速、高效地找到并执行对应的[[中断处理程序]]，而无需进行复杂的搜索或判断。

## 工作机制
1.  **中断发生**: [[硬件]]或软件产生一个[[中断]]，并向[[中央处理器 (CPU)]]提供一个唯一的**[[中断向量号]]**（Interrupt Vector Number），范围通常是0-255。
2.  **查找IVT**: [[中央处理器 (CPU)]]使用这个[[中断向量号]]作为索引，在[[中断向量表]]中查找对应的条目。
3.  **获取地址**: 该条目中存储着相应[[中断处理程序]]的起始[[内存]]地址。
4.  **跳转执行**: [[中央处理器 (CPU)]]保存当前[[进程 (Process)]]的上下文（如[[EIP]]、[[CS]]、[[EFLAGS寄存器]]等），然后跳转到获取到的地址，开始执行[[中断处理程序]]。
5.  **中断返回**: [[中断处理程序]]执行完毕后，通过`iret`指令，[[中央处理器 (CPU)]]恢复之前保存的上下文，返回到被中断的[[代码]]继续执行。

## 在x86实模式下的结构
- **固定位置**: 在x86[[实模式]]下，IVT固定存放在[[物理内存]]的最开始的1KB空间（地址`0x00000`到`0x003FF`）。
- **结构**:
    - 共256个条目（对应0-255号[[中断向量]]）。
    - 每个条目占用4个字节，包含一个[[中断处理程序]]的远地址（`段基址:段内偏移`）。

## 与IDT的区别
- **IVT**: 主要用于[[实模式]]。
- **[[中断描述符表 (IDT)]]**: 用于[[保护模式]]，是IVT的升级版。IDT中的条目不再是简单的地址，而是结构更复杂的[[门描述符]]，提供了[[特权级]]检查等更完善的保护机制。
