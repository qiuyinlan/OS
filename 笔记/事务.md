# 事务 (Transaction)

在[[数据库]]和[[文件系统]]领域，**事务**指的是一个**不可分割的逻辑工作单元**。它由一个或多个操作组成，这些操作要么全部成功执行，要么全部不执行，不会停留在中间状态。

## ACID特性
一个可靠的事务系统必须遵循[[ACID]]原则：
1.  **[[原子性]]**: 事务是原子的，不可再分。所有操作要么全部完成，要么全部回滚。
2.  **[[一致性|一致性]]**: 事务必须使[[数据库]]从一个有效状态转移到另一个有效状态。
3.  **[[隔离性|隔离性]]**: [[并发]]执行的多个事务之间互不干扰。
4.  **[[持久性|持久性]]**: 一旦事务提交，其结果就是永久性的，即使系统崩溃也不会丢失。

## 为什么需要事务？
- **保证数据完整性**: 在执行像“银行转账”（从A账户减钱，向B账户加钱）这样的多步操作时，事务可以保证即使中途发生断电或系统崩溃，账户的总金额也不会出错。
- **简化并发控制**: 事务的[[隔离性|隔离性]]使得程序员在编写[[并发]][[程序]]时，可以不必过多地担心复杂的[[竞争条件]]。

## 在文件系统中的应用
现代的**[[日志]]文件系统**（Journaling File System），如ext4、NTFS，也借鉴了[[数据库]]的事务思想。
- 当需要执行一系列磁盘写入操作时（例如，创建一个新[[文件]]，需要修改[[目录项]]、[[inode位图]]和[[数据块]]），[[文件系统]]会先把这些操作记录在一段称为“[[日志]]”的特殊区域。
- 只有当所有操作都成功记录到[[日志]]中后，才会真正地将[[数据]]写入[[硬盘]]的最终位置。
- 如果在写入过程中发生[[系统崩溃]]，系统重启后可以通过检查[[日志]]来恢复或完成未完成的操作，从而保证了[[文件系统]]的[[一致性|一致性]]。
