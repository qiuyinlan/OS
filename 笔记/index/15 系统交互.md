# 第15章 系统交互

本章将实现[[进程间通信]]、[[fork]]、[[exec]]、[[wait]]、[[exit]]等核心[[系统调用]]，并构建一个简单的`shell`。

## 15.1 fork 的原理与实现

### 15.1.1 什么是 fork
- **`fork()`系统调用**: 创建一个与父进程几乎完全相同的新进程（子进程）。
- **返回值**:
    - 父进程中返回子进程的`pid`。
    - 子进程中返回`0`。
    - 失败返回`-1`。
- **作用**: 克隆进程，实现进程的“分身术”。父子进程在`fork`调用之后，“分道扬镳”，各自继续执行。

### 15.1.2 fork 的实现
- **核心思想**: 复制旧进程（父进程）的所有资源给新进程（子进程），然后使子进程进入就绪队列。
- **复制的资源**:
    1.  [[PCB]] (`task_struct`)。
    2.  程序体（代码段、数据段）。
    3.  用户栈。
    4.  内核栈。
    5.  虚拟地址池(`userprog_vaddr`)。
    6.  页表。
- **`copy_pcb_vaddrbitmap_stack0()`**: 复制[[PCB]]、虚拟地址位图和内核栈。
- **`copy_body_stack3()`**: 复制进程体（代码和数据）和用户栈。通过[[内核空间]]中转，一页一页地将父进程[[用户空间]]数据复制到子进程[[用户空间]]。
- **`build_child_stack()`**: 为子进程构建`thread_stack`和修改返回值。
    -   子进程的`eax`在`intr_stack`中被置为`0`（`fork`返回值）。
    -   `thread_stack`的`eip`被设置为`intr_exit`地址，使子进程直接从中断返回，从`fork`之后的代码继续执行。
- **`update_inode_open_cnts()`**: 更新子进程继承的文件`inode`打开计数。
- **`sys_fork()`**: `fork`的内核实现，封装上述复制和构建函数。

## 15.1.3 添加 `fork` 系统调用与实现 `init` 进程
- **`init` 进程**: Linux系统中第一个启动的用户级进程，`pid`为1。负责回收所有子进程的资源（孤儿进程的“养父”）。
- **实现**: 在`thread_init()`中通过`process_execute()`创建`init`进程。`init`进程会调用`fork()`派生子进程。

## 15.2 从键盘获取输入 (Read 系统调用)
- **`sys_read(fd, buf, count)` 改进**:
    -   当`fd`为`stdin_no`时，从键盘缓冲区`kbd_buf`中读取数据（通过`ioq_getchar`）。
    -   实现了从标准输入设备键盘读取数据的功能。

## 15.3 添加 `putchar`、`clear` 系统调用
- **`putchar(char_asci)`**: 输出单个字符，内核实现直接调用`console_put_char`。
- **`clear()`**: 清空屏幕，内核实现`cls_screen`通过汇编操作显存实现。

## 15.4 实现一个简单的 shell
- **`shell`**: [[操作系统]]与用户交互的“外壳”程序。
- **核心功能**: 获取用户输入，分析命令，执行内部命令或外部命令。

### 15.4.1 shell 雏形
- **`cmd_len`**: 最大命令行输入长度（如128字节）。
- **`MAX_ARG_NR`**: 最大参数数量（如15个）。
- **`print_prompt()`**: 输出命令提示符（如`[rabbit@localhost /]$`）。
- **`readline(buf, count)`**: 从键盘缓冲区读取用户输入，直到回车或缓冲区满。处理退格键。
- **`my_shell()`**: shell主循环，输出提示符，读取命令。

### 15.4.2 添加 `Ctrl+u` 和 `Ctrl+l` 快捷键
- **实现原理**: 在`readline()`中，根据`Ctrl`组合键（如`'l'-'a'`）对应的ASCII码差值，执行清屏或清除输入操作。
    - `Ctrl+l`: 清屏（调用`clear()`），不清除已输入内容。
    - `Ctrl+u`: 清除当前行输入。

### 15.4.3 解析键入的字符
- **`cmd_parse(cmd_str, argv, token)`**: 解析命令行字符串`cmd_str`，以`token`为分隔符，将各单词指针存入`argv`数组。
    -   处理命令字和参数之间的空格。
    -   将`token`字符替换为字符串结束符`\0`，使`argv`中的每个元素成为独立的字符串。

### 15.4.4 添加系统调用
- 批量将`fs.c`中实现的`sys_xxx`函数注册到`syscall_table`中，包括`getcwd`、`open`、`close`、`lseek`、`unlink`、`mkdir`、`opendir`、`closedir`、`chdir`、`rmdir`、`readdir`、`rewinddir`、`stat`、`ps`。
- **`ps()`**: 打印任务列表，显示`pid`、`ppid`、状态、运行时间片和进程名。

### 15.4.5 路径解析转换
- **`wash_path(old_abs_path, new_abs_path)`**: 将包含`.`和`..`的绝对路径`old_abs_path`转换为不含它们的实际路径`new_abs_path`。
- **`make_clear_abs_path(path, final_path)`**: 将用户输入的路径（可能为相对路径或含`.`、`..`）转换为不含`.`、`..`的绝对路径`final_path`。

### 15.4.6 实现 `ls`、`cd`、`mkdir`、`ps`、`rm` 等命令
- **内置命令**: `shell`的内置命令（`buildin_xxx`）直接在内核中实现，不作为单独程序。
- **编写规则**:
    1.  命令函数名前缀`buildin_`。
    2.  参数为`argc`和`argv`。
    3.  调用同功能的[[系统调用]]实现。
    4.  在[[系统调用]]前，使用`make_clear_abs_path`将路径转换为绝对路径。

## 15.5 加载用户进程

### 15.5.1 实现 `exec`
- **`exec()`系统调用**: 用一个可执行文件的进程体替换当前进程的进程体（代码、数据、堆、栈），从而执行新程序。新程序的`pid`不变。
- **`Elf32_Ehdr`, `Elf32_Phdr`**: [[ELF]]文件头和程序头结构体，用于解析[[ELF]]格式的用户程序。
- **`segment_load(fd, offset, filesz, vaddr)`**: 将[[ELF]]文件中指定段加载到内存的指定虚拟地址。
    -   为新进程分配内存（使用`get_a_page`）。
    -   通过`sys_lseek`和`sys_read`从文件系统加载数据。
- **`load(path)`**: 从[[文件系统]]加载[[ELF]]用户程序。
    -   打开文件，读取[[ELF]]头并校验。
    -   遍历程序头，调用`segment_load`加载`PT_LOAD`类型的段。
    -   返回程序的入口地址`e_entry`。
- **`sys_execv(path, argv)`**: `exec`的内核实现。
    -   调用`load(path)`加载程序。
    -   修改当前进程的[[PCB]]（更新进程名）。
    -   修改当前进程的内核栈中保存的`intr_stack`信息，使其`eip`指向新程序的入口地址，`esp`指向用户空间最高地址，并传递`argc`, `argv`参数。
    -   通过`jmp intr_exit`从中断返回，执行新程序。

### 15.5.3-15.5.4 加载硬盘上的用户程序执行
- **`compile.sh`脚本**: 用于编译用户程序（如`prog_no_arg.c`, `prog_arg.c`）为[[ELF]]格式，并写入[[硬盘]]（`hd60M.img`）。
- **`start.S`**: 用户程序的真正入口点（CRT的简化版），负责为`main`函数准备`argc`和`argv`参数，然后调用`main`。

## 15.6 实现系统调用 `wait` 和 `exit`

### 15.6.1 `wait` 和 `exit` 的作用
- **`exit()`**: 使进程主动退出，结束运行。将进程的返回值传递给内核。
- **`wait()`**: [[阻塞]]父进程，直到任意一个子进程结束运行。用于解决父子进程间的[[同步]]问题，并获取子进程的返回值。

### 15.6.2 孤儿进程和僵尸进程
- **[[孤儿进程]]**: 父进程先于子进程结束，子进程被`init`进程收养。
- **[[僵尸进程]]**: 子进程结束运行但父进程没有调用`wait()`来获取其返回值。子进程的[[PCB]]没有被回收，但进程体已消失。

### 15.6.3 基础代码
- **`exit_status`**: 在[[PCB]]中增加成员记录进程退出状态。
- **`free_a_phy_page(pg_phy_addr)`**: 根据物理页框地址在[[位图]]中清零对应位。
- **`pid`池管理**: 实现`pid_pool`结构和`allocate_pid()`, `release_pid()`函数，通过[[位图]]管理`pid`的分配与释放。
- **`thread_exit(thread_over, need_schedule)`**: 回收任务的[[PCB]]和页表，并从调度队列中移除。
- **`pid2thread(pid)`**: 根据`pid`查找对应的[[PCB]]。

### 15.6.4 实现 `wait` 和 `exit`
- **`release_prog_resource(release_thread)`**: 释放[[用户进程]]资源（页表中的物理页、虚拟内存池、关闭打开的文件）。
- **`sys_wait(status)`**: `wait`的内核实现。
    -   优先处理已挂起的子进程（`TASK_HANGING`）。
    -   如果没有已挂起的子进程但有其他子进程，则[[阻塞]]父进程（`TASK_WAITING`）。
    -   获取子进程`exit_status`，调用`thread_exit`回收子进程资源，返回子进程`pid`。
- **`sys_exit(status)`**: `exit`的内核实现。
    -   保存退出状态`status`。
    -   将所有子进程过继给`init`进程。
    -   释放自身资源（除[[PCB]]）。
    -   唤醒正在等待的父进程。
    -   [[阻塞]]自己（`TASK_HANGING`），等待父进程回收[[PCB]]。

### 15.6.5 实现 `cat` 命令
- **`cat`命令**: 简单的文件查看工具，支持从文件或标准输入读取内容并输出。
- **实现**:
    -   用户程序`cat.c`中实现`main`函数。
    -   若`argc=1`（无参数），从标准输入`stdin_no`读取。
    -   若`argc=2`（带文件名参数），打开文件，循环`read`文件内容并通过`write`输出。

## 15.7 管道 (`pipe`)

### 15.7.1 管道的原理
- **[[管道]]**: [[进程间通信]]的一种方式，被视为存在于内存中的文件，不存储在[[文件系统]]上。
- **[[环形缓冲区]]**: [[管道]]的底层实现，类似于[[ioqueue]]。
- **两端**: 一端用于读（`pipefd[0]`），一端用于写（`pipefd[1]`）。
- **父子进程通信**: `fork`后，子进程继承父进程的[[管道]][[文件描述符]]，实现通信。通常父子进程分别关闭不使用的[[管道]][[文件描述符]]。

### 15.7.2 管道的设计
- **`file`结构复用**: 不为[[管道]]创建新的数据结构，而是复用现有的`struct file`。
    - `fd_flags`用于标记为`PIPE_FLAG`。
    - `fd_inode`指向[[管道]]的[[环形缓冲区]]（内核内存）。
    - `fd_pos`用于记录[[管道]]的打开数。
- **最大数据量**: 管道能够传递的最大数据量是环形缓冲区的大小减一。

### 15.7.3 管道的实现
- **`ioq_length(ioq)`**: 返回[[环形缓冲区]]中的数据长度。
- **`sys_pipe(pipefd[2])`**: 创建[[管道]]。
    1.  从`file_table`获取空闲`file`结构。
    2.  为`file->fd_inode`分配一页内核内存作为[[环形缓冲区]]，并初始化。
    3.  设置`file->fd_flag = PIPE_FLAG`。
    4.  设置`file->fd_pos = 2`（两个描述符）。
    5.  调用`pcb_fd_install`两次，为当前进程安装两个[[文件描述符]]（`pipefd[0]`读，`pipefd[1]`写）。
- **`pipe_read(fd, buf, count)`**: 从[[管道]]读取数据。
    -   根据[[管道]]中数据量和`count`选择较小值，调用`ioq_getchar`逐字节读取。
- **`pipe_write(fd, buf, count)`**: 向[[管道]]写入数据。
    -   根据[[环形缓冲区]]剩余空间和`count`选择较小值，调用`ioq_putchar`逐字节写入。
- **文件系统修改**:
    - `sys_close()`: 增加对[[管道]]描述符的关闭处理。若[[管道]]上的描述符都关闭，释放其[[环形缓冲区]]。
    - `sys_write()`: 增加对[[管道]]写入的处理，可重定向标准输出到[[管道]]。
    - `sys_read()`: 增加对[[管道]]读取的处理，可重定向标准输入从[[管道]]读取。
    - `fork()`: 增加[[管道]]打开计数的更新。
    - `exit()`: 增加[[管道]]资源的释放。

### 15.7.4 利用管道实现进程间通信
- 用户程序`prog_pipe.c`演示父子进程通过[[管道]]进行通信。
    - 父进程关闭读端，向写端写入数据。
    - 子进程关闭写端，从读端读取数据。

### 15.7.5 在 shell 中支持管道
- **`sys_fd_redirect(old_local_fd, new_local_fd)`**: 将[[文件描述符]]`old_local_fd`重定向到`new_local_fd`。
    - 原理: 将`fd_table`中`old_local_fd`的值替换为`new_local_fd`的值。
- **shell对管道的处理**:
    1.  检测命令行中是否存在管道符`|`。
    2.  若存在，调用`sys_pipe`创建[[管道]]。
    3.  将第一个命令的标准输出重定向到[[管道]]的写端。
    4.  执行第一个命令。
    5.  将后续命令的标准输入和标准输出重定向到[[管道]]。
    6.  执行中间命令。
    7.  恢复最后一个命令的标准输出到屏幕。
    8.  恢复标准输入到键盘。
    9.  关闭[[管道]][[文件描述符]]。
