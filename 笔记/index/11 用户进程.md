# 第11章 用户进程

本章的目标是实现从内核态（特权级0）到用户态（特权级3）的过渡，创建真正的[[用户进程]]。

## 11.1 任务状态段 (TSS)
[[TSS]] 是 x86 架构中为了实现硬件多任务而设计的特殊数据段。

### 11.1.1-11.1.3 TSS 的作用


- **硬件多任务的设想**: Intel 最初的设计是，每个任务（进程/线程）都拥有一个独立的[[TSS]]。[[TSS]]中保存了任务切换时需要保存/恢复的所有[[寄存器]]状态（上下文快照）。任务切换通过`call`或`jmp`到一个指向新任务[[TSS]]的[[段选择子]]来由硬件自动完成。
- **LDT (局部描述符表)**: Intel 还设想每个任务有自己的[[LDT (Local Descriptor Table)]]，用于存放任务私有的段描述符，以实现任务间的隔离。
- **TR (任务寄存器)**: `TR`寄存器指向当前正在运行任务的[[TSS]]。硬件任务切换的本质就是改变`TR`的指向。
单核 CPU 要想实现多任务，唯一的方案就是多个任务共享同一个 CPU，也就是只能让 CPU 在多个任 务间轮转，让所有任务轮流使用 CPU，除此之外还真别无他法。
 TSS 是由程序员“提供”的，由 CPU 来“维护”。“提供”就是指 TSS 是程序员为任务单独定义的一个结构体变量，“维护”是指 CPU 自动用此结构体变量保存任务的状态（任务的上下 文环境，寄存器组的值）和自动从此结构体变量中载入任务的状态。
### 11.1.5 现代操作系统的选择
- **硬件切换的缺点**:
    - **效率低**: 硬件任务切换需要保存和恢复完整的寄存器状态，消耗数百个时钟周期，非常慢。
    - **灵活性差**: 强依赖于GDT，不易扩展到大量任务。
    - **平台相关**: 这种机制是x86特有的，不利于[[操作系统]]的跨平台移植。
- **Linux/现代OS的做法 (软件切换)**:
    - **抛弃硬件切换**: 不使用`call`/`jmp`到TSS的方式进行任务切换，而是采用软件方式（如我们之前实现的`switch_to`）。
    - **保留TSS**: 尽管不用于任务切换，但**必须保留一个TSS**。
    - **TSS的唯一作用**: 当任务从低[[特权级]]（用户态，Ring 3）进入高[[特权级]]（内核态，Ring 0）时（例如发生[[中断]]或[[异常 (Exception)]]），[[中央处理器 (CPU)]]硬件需要知道在哪里找到高[[特权级]]的[[栈]]。这个**内核栈的指针（`ss0:esp0`）必须从当前`TR`寄存器指向的TSS中获取**。
- **我们的实现**: 效仿Linux，整个系统只使用一个全局的[[TSS]]。任务切换时，我们只更新这个[[TSS]]中的`esp0`字段，使其指向新任务的内核栈顶即可。

## 11.2 定义并初始化TSS (`tss.c`)
1.  **定义`struct tss`**: 根据硬件手册定义[[TSS]]的C语言结构体。
2.  **实例化一个全局TSS**: `static struct tss tss;`
3.  **在GDT中添加TSS描述符**:
    -   在`tss_init()`中，创建一个TSS段描述符。
    -   将其安装到[[GDT-GDTR-LGDT|GDT]]中一个固定的位置（如第4个描述符）。
4.  **加载TR寄存器**:
    -   在`tss_init()`的最后，执行`ltr`指令，将TSS选择子加载到`TR`寄存器。此后`TR`不再改变。
5.  **提供`update_tss_esp()`函数**: 此函数用于在任务切换时，更新全局`tss`结构中的`esp0`字段，使其指向即将运行任务的内核栈顶。

## 11.3 实现用户进程

### 11.3.2-11.3.3 用户进程的地址空间和页表
- **独立地址空间**: 与线程不同，[[用户进程]]拥有自己独立的4GB虚拟地址空间，这意味着每个进程都需要有自己的一套页表。
- **虚拟地址位图 (`userprog_vaddr`)**: 在进程的[[PCB]]中增加一个`struct virtual_addr`成员，用于管理该进程**用户空间**（0 - 3GB）虚拟地址的分配情况。
- **创建页表 (`create_page_dir`)**:
    1.  为新进程的页目录表申请一页内核内存。
    2.  **共享内核空间**: 将内核的页目录项（PTEs for 3-4GB）复制到新进程页目录表的相同位置。这样，所有用户进程的虚拟地址空间的高1GB都映射到同一个内核物理内存，实现了内核共享。
    3.  **递归映射**: 将新页目录表自己的物理地址填入其最后一个页目录项，实现`0xfffff000`的递归访问。

### 11.3.4-11.3.5 进入特权级3
- **目标**: 从内核态（Ring 0）安全、正确地切换到用户态（Ring 3）去执行用户代码。
- **方法**: 只能通过`iret`或`iretd`指令实现从高到低的特权级转移。
- **“伪造”中断返回**:
    1.  在即将运行的用户进程的**内核栈**上，手动构建一个`intr_stack`帧。
    2.  **填充关键寄存器值**:
        -   `CS`: 指向用户代码段的选择子（DPL=3）。**RPL必须设为3**。
        -   `EIP`: 指向用户程序的入口地址。
        -   `DS`/`ES`/`FS`: 指向用户数据段的选择子（DPL=3）。
        -   `SS`: 指向用户栈段的选择子（DPL=3）。
        -   `ESP`: 指向为用户进程分配的3级栈的栈顶。
        -   `EFLAGS`: **`IF`位必须为1**（开中断），**`IOPL`位必须为0**（禁止用户态I/O端口访问）。
    3.  **执行跳转**: `jmp`到`intr_exit`，利用`intr_exit`中的`pop`系列指令和`iretd`，将我们伪造的上下文加载到[[中央处理器 (CPU)]]中。`iretd`执行时，检测到`CS.RPL=3`，便会完成到Ring 3的特权级转换。

### 11.3.6-11.3.10 进程创建与调度
- **`process_execute(func, name)`**: 创建进程的入口函数。
    -   创建[[PCB]]、初始化线程信息、创建用户虚拟地址位图、创建页表。
    -   调用`thread_create`，但这次线程体不再是用户函数，而是`start_process`。用户函数`func`作为参数传给`start_process`。
- **`start_process(func)`**:
    -   在当前进程（此时已是新创建的用户进程）的内核栈上构建用于“伪造中断返回”的`intr_stack`。
    -   将`func`的地址设为`EIP`。
    -   `jmp`到`intr_exit`，完成到Ring 3的切换。
- **`process_activate(task)`**: 在调度器`schedule`中，切换任务前调用。
    -   调用`page_dir_activate`，将新任务的页目录表地址加载到`CR3`寄存器，完成地址空间切换。
    -   如果新任务是进程（`pgdir != NULL`），则调用`update_tss_esp`更新TSS中的`esp0`。
