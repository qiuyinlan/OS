# 缺页异常 (Page Fault)

**缺页异常**（Page Fault）是[[操作系统]]中[[虚拟内存]]管理的一种核心机制。当[[中央处理器 (CPU)]]尝试访问一个在[[虚拟地址空间]]中存在、但尚未加载到[[物理内存]]（RAM）中的[[页面]]时，由[[内存管理]]单元（MMU）触发的一种[[异常 (Exception)]]。

缺页异常**不是一个错误**，而是一种常规事件，是[[操作系统]]实现“按需分页”（Demand Paging）的正常流程。

## 缺页异常的类型
1.  **软缺页（Minor Fault）**: 请求的[[页面]]其实**在[[物理内存]]中**，但[[操作系统]]尚未在当前[[进程 (Process)]]的[[页表]]中建立映射。例如，多个[[进程 (Process)]]共享的库文件，已由其他[[进程 (Process)]]加载。[[操作系统]]只需在[[页表]]中添加正确的映射即可，速度很快。
2.  **硬缺页（Major Fault）**: 请求的[[页面]]**不在[[物理内存]]中**，必须从[[硬盘]]等二级存储设备中加载。这个过程涉及磁盘I/O，速度很慢，是影响性能的主要因素。
3.  **无效缺页（Invalid Fault）**: [[进程 (Process)]]试图访问一个非法的[[内存]]地址（例如，访问权限不足，或地址超出了其[[地址空间]]范围）。这种情况是真正的程序错误，[[操作系统]]通常会终止该[[进程 (Process)]]（例如，在Linux中引发“段错误”`Segmentation Fault`）。

## 处理流程（针对有效的硬缺页）
1.  **陷入内核 (Trap)**: [[中央处理器 (CPU)]]将控制权转移给[[操作系统]]的缺页[[中断处理程序]]。
2.  **检查合法性**: [[操作系统]]检查[[进程 (Process)]]的[[页表]]，判断这次访问是否合法。
3.  **找到空闲页帧**: 在[[物理内存]]中找到一个空闲的[[页帧]]。如果没有空闲的，则需要运行**页面置换算法**（如LRU），将一个现有的[[页面]]换出到[[硬盘]]。
4.  **加载数据**: 从[[硬盘]]中读取目标[[页面]]的数据，加载到找到的[[页帧]]中。
5.  **更新页表**: 修改[[进程 (Process)]]的[[页表]]，建立[[虚拟地址]]到新加载[[物理地址]]的映射，并设置相应的标志位（如“存在位”）。
6.  **返回并重启**: 从[[中断处理程序]]返回，并**重新执行**导致异常的那条[[指令]]。此时访问将成功。
