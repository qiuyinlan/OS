# 进程间通信 (Inter-Process Communication - IPC)

**进程间通信**（IPC）是[[操作系统]]提供的一系列机制，用于让各自独立的[[进程 (Process)]]能够相互交换[[数据]]和[[同步]]其行为。

## 为什么需要IPC？
- **独立性**: 在现代[[操作系统]]中，[[进程 (Process)]]拥有独立的[[虚拟地址空间]]，这保证了[[进程 (Process)]]之间的隔离和安全，但也意味着它们不能直接读写对方的[[内存]]。
- **协作**: 很多复杂的任务需要多个[[进程 (Process)]]协同工作才能完成。IPC打破了[[进程 (Process)]]间的壁垒，使它们能够合作。例如，一个[[进程 (Process)]]从网络接收数据，另一个[[进程 (Process)]]负责处理和显示这些数据。
- **模块化**: 将一个大型[[程序]]拆分成多个小[[进程 (Process)]]，每个[[进程 (Process)]]负责一个具体功能。这使得[[程序]]更容易设计、调试和维护。

## 主要的IPC机制
1.  **管道 (Pipe)**
    -   **匿名管道**: 只能在有亲缘关系的[[进程 (Process)]]（如父子[[进程 (Process)]]）之间使用。它是一个单向的[[数据]]流，一端写入，另一端读出。
    -   **命名管道 (FIFO)**: 在文件系统中拥有一个名字，允许任何知道这个名字的[[进程 (Process)]]之间进行通信，因此可以用于非亲缘关系的[[进程 (Process)]]。

2.  **消息队列 (Message Queue)**
    -   一个由[[内核]]维护的消息链表。[[进程 (Process)]]可以向队列中发送消息，或从队列中读取消息。
    -   克服了管道只能单向通信、缓冲区大小有限的缺点。

3.  **共享内存 (Shared Memory)**
    -   [[操作系统]]将同一块[[物理内存]]映射到多个[[进程 (Process)]]各自的[[虚拟地址空间]]中。
    -   **速度最快**的IPC方式，因为[[数据]]不需要在[[用户空间]]和[[内核空间]]之间来回复制。
    -   **挑战**: 必须使用其他[[同步]]机制（如[[信号量 (Semaphore)]]或[[锁 (Lock)]]）来保证[[进程 (Process)]]对共享[[内存]]的访问是[[互斥 (Mutual Exclusion)]]的，否则会产生[[竞争条件]]。

4.  **信号量 (Semaphore)**
    -   它本身是一种[[同步]]机制，但也可用于[[进程 (Process)]]间[[同步]]，因此也常被归类为IPC。
    -   通过控制一个计数器来协调对共享资源的访问。

5.  **信号 (Signal)**
    -   一种较为复杂的通信方式，用于通知接收[[进程 (Process)]]某个[[异步]]事件已经发生。例如，用户按下`Ctrl+C`会向[[进程 (Process)]]发送`SIGINT`信号。

6.  **套接字 (Socket)**
    -   最通用的IPC机制，不仅可以在同一台机器上的[[进程 (Process)]]间通信，还可以跨网络在不同机器上的[[进程 (Process)]]间通信。
