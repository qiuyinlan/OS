# 系统调用子功能表 (syscall_table)

**系统调用子功能表**（`syscall_table`）是[[操作系统]] [[内核]]中的一个核心[[数据]]结构，它本质上是一个**函数指针数组**。它充当了[[用户空间]]和[[内核空间]]之间的“分发表”或“路由表”。

## 核心作用
- **映射系统调用号与内核函数**: 当一个[[应用程序]]执行[[系统调用]]时，它会提供一个**[[系统调用号]]**来指明它想请求哪种服务。[[内核]]使用这个[[系统调用号]]作为`syscall_table`数组的索引，从而找到并执行对应的[[内核]]处理函数。
- **安全接口**: 它是[[用户空间]]请求[[内核]]服务的唯一、受控的入口点，确保了[[应用程序]]不能随意调用[[内核]]内部的任意函数，是[[操作系统]]安全模型的重要一环。

## 工作流程
1.  **用户程序请求**: [[应用程序]]准备好[[系统调用]]所需的参数，并将特定的[[系统调用号]]加载到一个约定的[[寄存器]]中（在x86-32的[[Linux]]中通常是`eax`[[寄存器]]）。
2.  **触发中断**: [[应用程序]]执行一条特殊的[[指令]]（如 `int 0x80`），这会触发一个[[软件]][[中断]]，使[[中央处理器 (CPU)]]从[[用户空间]]切换到[[内核空间]]，并将控制权交给[[内核]]的[[系统调用]]总入口。
3.  **内核分发**: [[系统调用]]总入口程序从`eax`[[寄存器]]中获取[[系统调用号]]。
4.  **查询表**: 以该[[系统调用号]]作为索引，在`syscall_table`中查找对应的函数指针。
5.  **执行服务**: 调用该函数指针所指向的[[内核]]函数（如`sys_read`, `sys_write`等），完成用户请求的服务。
6.  **返回结果**: [[内核]]函数执行完毕后，将返回值存入`eax`[[寄存器]]，然后通过`iret`[[指令]]返回[[用户空间]]。

## 在本项目中的实现
在我们的[[操作系统]]项目中，`syscall_table`是一个定义在`syscall.c`中的`void*`类型的数组。在`syscall_init`函数中，我们会将所有已实现的[[系统调用]]处理函数（如`sys_getpid`）的地址填入这个数组的相应位置，从而完成[[系统调用]]机制的初始化。
